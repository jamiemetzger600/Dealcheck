# Version Management Guide

## Overview

All version numbers in the extension are managed centrally through `version.js`. This ensures consistency across all files and eliminates hardcoded version numbers.

---

## Architecture

### Single Source of Truth

**File: `version.js`**
```javascript
const VERSION = '2.2.0';
```

This is the ONLY place where the version number should be manually edited.

### How It Works

1. **version.js** exports the version to `window.EXTENSION_VERSION`
2. **manifest.json** contains the version (updated via script)
3. All other files read from `window.EXTENSION_VERSION`

### Files Using Central Version

| File | Usage |
|------|-------|
| `version.js` | Source of truth |
| `manifest.json` | Chrome extension version |
| `content.js` | UI display version |
| `deals-dashboard.js` | Console logging |
| All PDFs/exports | Generated content |

---

## How to Update Version

### Method 1: Automated Script (Recommended)

```bash
./update-version.sh 2.2.1
```

This script will:
1. ✅ Update `version.js`
2. ✅ Update `manifest.json`
3. ✅ Show verification of changes
4. ✅ Optionally create git commit

### Method 2: Manual Update

If you prefer manual updates:

1. **Edit version.js**
   ```javascript
   const VERSION = '2.2.1';  // Update this line
   ```

2. **Edit manifest.json**
   ```json
   "version": "2.2.1"  // Update this line
   ```

3. **Verify in browser**
   - Reload extension in Chrome
   - Check version displays correctly in all locations

### 1. Extension Popup (content.js)

- **Format**: `v2.2.0`
- **Source**: `window.EXTENSION_VERSION`

### 2. Dashboard (deals-dashboard.js)
- **Location**: Console logs
- **Format**: `Initializing Deal Aggregator v2.2.0`
- **Source**: `window.EXTENSION_VERSION`

### 3. PDF Exports
- **Location**: Footer of generated PDFs
- **Format**: `Generated by Max Price Deal Analyzer v2.2.0`
- **Source**: `window.EXTENSION_VERSION`

### 4. Chrome Extension Manager
- **Location**: chrome://extensions/
- **Format**: `2.2.0`
- **Source**: `manifest.json`

## Version Numbering Convention

We follow **Semantic Versioning (SemVer)**:

```
MAJOR.MINOR.PATCH
  2  .  2  .  0
```

### When to Increment

**MAJOR version** (2.x.x → 3.0.0)
- Breaking changes
- Major UI/UX overhaul
- Incompatible data format changes

**MINOR version** (2.2.x → 2.3.0)
- New features
- Significant enhancements
- New API endpoints

**PATCH version** (2.2.0 → 2.2.1)
- Bug fixes
- Small tweaks
- Documentation updates
- Performance improvements

### Examples

```bash
# Bug fix
./update-version.sh 2.2.1

# New feature
./update-version.sh 2.3.0

# Breaking change
./update-version.sh 3.0.0
```

## Git Workflow

### Standard Release Process

1. **Make your code changes**
   ```bash
   # Make changes to files...
   ```

2. **Update version**
   ```bash
   ./update-version.sh 2.2.1
   # Script will offer to commit version.js and manifest.json
   ```

3. **Commit your code changes**
   ```bash
   git add .
   git commit -m "Fix: Resolve notification permission bug (v2.2.1)"
   ```

4. **Push to remote**
   ```bash
   git push origin feature/your-branch
   ```

### Quick Fixes (Patch Versions)

For small fixes that only need a version bump:

```bash
# Fix code
git add your-fixed-files.js

# Update version (it will commit version files)
./update-version.sh 2.2.1

# Commit the fixes
git commit -m "Fix: Brief description (v2.2.1)"

# Push
git push
```

## Troubleshooting

### Version Not Updating

**Problem**: Old version still showing after update

**Solutions**:
1. Hard reload extension in chrome://extensions/
2. Clear browser cache
3. Close and reopen Chrome
4. Check that version.js loads before other scripts

### Script Permission Denied

**Problem**: `./update-version.sh: Permission denied`

**Solution**:
```bash
chmod +x update-version.sh
./update-version.sh 2.2.1
```

### Version Mismatch

**Problem**: Different versions in different places

**Check**:
```bash
# Check all version locations
grep "const VERSION = " version.js
grep '"version"' manifest.json
```

**Fix**:
```bash
# Run the update script to synchronize
./update-version.sh 2.2.1
```

## FAQ

**Q: Can I still manually edit version.js?**  
A: Yes, but using the script is recommended to ensure manifest.json stays in sync.

**Q: What if I forget to update the version?**  
A: Use the script before committing. It will remind you of the current version.

**Q: Do I need to update version for every commit?**  
A: Update for every user-facing change. Internal refactoring may not need version bumps.

**Q: What about the "v" prefix?**  
A: `version.js` stores just the number (2.2.1). The "v" prefix is added by display code.

**Q: Can I automate this in CI/CD?**  
A: Yes! The script can be integrated into your build pipeline.

## Summary

**Before (Old System):**
```javascript
// content.js
const VERSION = 'v1.9.21';  // ❌ Hardcoded

// deals-dashboard.js
console.log('Initializing Deal Aggregator v2.2.0');  // ❌ Hardcoded
```

**After (New System):**
```javascript
// version.js
const VERSION = '2.2.1';  // ✅ Single source

// content.js
const VERSION = window.EXTENSION_VERSION ? `v${window.EXTENSION_VERSION}` : 'v2.2.0';  // ✅ Dynamic

// deals-dashboard.js
const version = window.EXTENSION_VERSION || '2.2.0';  // ✅ Dynamic
console.log(`Initializing Deal Aggregator v${version}`);
```

**Result:** One version to rule them all! 🎉
